## Findings

### Aggregate View: Boundary Contract

1. **[Medium][Fix now] The browser coverage contract accepts labels and aliases that are not the official mapping for their canonical ID.** `parseAdminKnowledgeProvinceCoverageList()` verifies only that every governed ID occurs once and that names are structurally valid; it does not check `currentName` or `legacyNames` against the versioned official fixture (`packages/contracts/src/youtube-discovery/index.ts:95-104`). The controller/API uses this parser as the fail-closed response boundary, while the selected values are passed to the suggestion gateway (`apps/api/src/admin/admin-youtube-discovery.controller.ts:10-25`; `packages/database/src/admin-youtube-discovery.ts:29-44`). The existing test builds all 34 rows by assigning Hanoi's name and metadata to every canonical ID and expects it to parse successfully (`tests/story-23-2-province-coverage-contract.test.ts:7-18`). This leaves an invalid cross-layer coverage response able to render a wrong official name/alias pair and send it to the AI request. It violates Story 23.2 AC1 and AC2, which require official aliases for each current unit and selected canonical geography plus official aliases only.

Disposition: fix now. Prevention: make the contract parser derive/validate the canonical ID-to-name/alias mapping from the shared governed reference, and add per-ID mismatch regressions.

### Spec-To-Implementation Reconciliation

2. **[Medium][Fix now] Immediate-run progress projects a safe error code but does not render its practical Vietnamese recovery context.** The projection includes the allowlisted `safeErrorCode` (`packages/database/src/admin-youtube-discovery.ts:269-278`) and the contract accepts codes including `search_timeout`, `eligibility_unavailable`, and `policy_revoked` (`packages/contracts/src/youtube-discovery/index.ts:66-71`). The Mission UI renders a generic status plus retry timestamp/count, but does not consume `safeErrorCode` (`apps/admin/app/knowledge/youtube-discovery/mission/mission.tsx:340-363`). The UI test passes `search_timeout`, `retry_exhausted`, and `policy_revoked` but asserts only a generic state label (`tests/admin-youtube-discovery-mission-ui.test.ts:146-166`). This does not meet Story 23.3's required safe retry/error context and practical Vietnamese failure recovery (`spec-23-3-run-confirmed-queries-immediately-and-show-progress.md:23,67`) or the Epic context's safe retry/error-context requirement (`epic-23-context.md:39`).

Disposition: fix now. Prevention: map the existing allowlisted codes to bounded Vietnamese recovery copy in the UI and add one rendered assertion for each recovery category; do not expose diagnostic payloads.

- Immediate-run admission itself is correctly bounded by policy/query locks, returns one active immediate run, and preserves scheduled cadence (`packages/database/src/admin-youtube-discovery.ts:256-278`; `tests/story-23-3-immediate-runs.integration.test.ts:14-88`).
- The normalized coverage producer is Knowledge-owned, aggregates only active cards with non-null canonical references, and derives names/aliases from the official fixture (`packages/database/src/admin-knowledge-coverage.ts:14-29`).
- A suggested query is intentionally editable before an operator persists or immediately runs it (`spec-23-2-show-province-coverage-and-propose-vietnamese-queries.md:23,66`; `mission.tsx:251-289`). The review did not treat free-text semantic geography matching as a defect because this intended edit path would make it unsound.

## Acceptance Verdict

- Story 23.2 AC1 and AC2 are not fail-closed at the response contract because canonical IDs are not bound to their official current-name and alias mapping.

The completed artifacts and focused unit/typecheck evidence demonstrate the rest of the reviewed behavior, but they do not outweigh these unresolved acceptance gaps. The two action items above are proposed remediation and have not been applied by this retrospective.
