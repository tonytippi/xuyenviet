- (constraint) Parent spine AD-3 binds persistence to Drizzle migrations and PostgreSQL.
- (constraint) Parent spine AD-5 and AD-6 bind Discovery to an explicit module owner with server-side audited mutations.
- (constraint) Parent spine AD-10 binds Gemini video analysis to the operator-controlled unscheduled youtube:capture script.
- (constraint) Parent spine AD-25, AD-26, AD-28, AD-31, and AD-32 bind Knowledge capture, ingestion, publication, audit, and actors; Discovery candidates must not enter those lifecycles.
- (decision) Discovery runs are PostgreSQL-backed and claimed by the existing Worker; API/admin creates commands and reads projections only. This prevents request-serving and platform cron variants from owning discovery execution.
- (decision) Accepted candidates enter a Discovery-owned intake queue only. They never create or link a Knowledge source, and an operator still starts youtube:capture manually. This prevents hidden source admission and preserves the manual capture boundary.
- (decision) Metadata triage calls use the existing AI Gateway adapter and Usage model. Gemini is reserved for the youtube:capture script. This prevents Discovery from acquiring a second Gemini credential or video-analysis path.
- (decision) One durable Discovery candidate is canonicalized by YouTube video ID; query and run appearances are child records. This prevents duplicate candidates and preserves discovery/ranking history.
- (decision) Candidate intake state is pending | accepted | deferred | skipped | blocked. Accepted is a Discovery-owned queue state, not Knowledge source creation or capture completion. This prevents intake review from being confused with capture or publication lifecycle.
- (decision) Candidates and safe audit/dedupe metadata retain for 180 days. Raw comment samples are not persisted; derived sanitized comment signals receive a shorter configuration-controlled TTL. This prevents indefinite retention of untrusted user input.
- (decision) Discovery policy is one versioned PostgreSQL-owned configuration record, mutable only through audited operator commands. Each run snapshots its policy version. This prevents scattered environment thresholds and unreproducible rankings.
- (decision) Worker retries failed YouTube API or AI Gateway discovery stages with bounded exponential backoff and safe terminal failure codes; later scheduled runs remain independent. This prevents infinite provider loops and lost operational visibility.
- (decision) Discovery reads and mutations are exposed only by role-protected admin API commands and read models; apps/admin remains a typed API client. This prevents presentation-layer domain ownership and unscoped operator access.
- (decision) Discovery has a global admin-controlled enabled switch and per-query enabled/paused schedules. The Worker creates due query runs under PostgreSQL lease/fencing; capture remains unscheduled and manual. This prevents global shutdown from being confused with per-query control and prevents overlapping work.
- (decision) Query planning combines system-generated proposals from coverage gaps, freshness risk, unresolved conflicts, and aggregated anonymized AI Ask demand with operator-managed queries. Both use one query proposal aggregate with attributable origin and audit. This prevents separate scheduling/ranking behavior for equivalent queries.
- (decision) AI Ask demand inputs are aggregated and anonymized operational signals only; no traveler prompt, user identity, conversation content, or raw answer is persisted in Discovery. This prevents Discovery observability from retaining traveler content.
- (decision) Discovery persists only bounded safe video/channel metadata, derived sanitized comment signals, score factors, safe run errors, and audits. It never persists raw comments, prompts/responses, provider payloads, video media, transcripts, credentials, cookies, raw source material, evidence spans, or traveler content. This prevents Discovery becoming a raw-source or sensitive-content store.
- (decision) Discovery owns deterministic eligibility and ranking after schema-validated AI triage. AI scores and recommendations are untrusted operational input and cannot bypass canonical URL validation, dedupe, blocked query/channel policy, or operator review state. This prevents model output from becoming authority.
- (reality) Existing operator intake is the Knowledge admin seed-batch command: it canonicalizes YouTube URLs, creates queued sources, and records duplicate/failed/pending batch items. Existing youtube:capture only claims queued sources.
- (decision) Accepted Discovery candidates are copied/exported by an audited operator action into the existing Knowledge seed-batch intake command; Discovery neither writes sources nor stores source links. The shared canonicalizer determines accepted/duplicate/failed intake outcomes, which remain Knowledge-owned. This makes the manual handoff executable without changing source ownership.
- (decision) Global Discovery disable is a stage-level revocation fence: before every provider call, candidate write, or retry/requeue write, the Worker compares its claimed policy version and enabled switch to current policy under its lease. A revoked in-flight run becomes cancelled with safe usage/audit outcome and cannot create further Discovery work.
- (decision) AI Gateway gains the dedicated youtube_discovery_triage model purpose requiring text input and structured extraction/schema capability, with versioned triage prompt and Usage purpose. Model catalog selection and missing pricing fail closed before a budgeted triage call.
- (decision) Discovery quota and budget admission uses PostgreSQL per-policy-period reservations made atomically before a provider call; a reservation expires or reconciles to persisted provider usage/cost. Unknown pricing or unavailable usage blocks a budgeted AI triage call. Retries require a new reservation and do not reuse a settled one.
- (decision) Discovery and Knowledge intake share one exported YouTube canonicalization contract accepting only documented https youtube.com/youtu.be individual-video forms, validating ID grammar and returning https://www.youtube.com/watch?v={id}. Discovery checks prior capture through a Knowledge-owned safe eligibility lookup keyed by canonical video ID, never by direct table access.
- (decision) Discovery is a registered Worker adapter with explicit readiness and operational telemetry vocabulary. System proposal generation/refresh is its separately leased, idempotent planning stage, governed by the global enablement fence.
- (decision) Simplicity override: one role-protected Discovery accept command calls the existing Knowledge intake API with the canonical URL, just as the existing admin UI does. It records accepted only after Knowledge reports submitted or duplicate; failed intake leaves the candidate pending with a safe error. No Discovery export table, source link, queue state machine, or direct source write is added.
- (decision) Simplicity override: Discovery does not enforce AI-cost budgets or quota reservations. It records existing provider/Usage telemetry where available; budget reservations, projected capacity, and hard cost caps are deferred. Discovery still uses bounded worker concurrency/retries and provider rate-limit failure handling.
